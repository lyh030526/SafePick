# 5주차: AI 상품 설명 위험 신호 분석

검증일: 2026-10-28 (한국 시간)

추가 기능: [구매 전 주의 수준 분류](risk-levels.md). 기존 원문 체크리스트 위에 높음·보통·낮음·판단 보류와 판정 근거/미확인 정보를 표시합니다. 아래의 초기 구현 기록에서 ‘등급 없음’은 이 확장 이전 상태입니다.

추가 검증: [실제 판매 페이지 12개 / 판매 중인 10개 분석 기록](validation/2026-10-28/week5-real-products/README.md). 아래 초기 6개 평가와 별도로 페이지를 새로 수집했으며, 발견한 인용 형식·중지 화면·옵션/메뉴 오인 보정을 반영했습니다. 최신 검증과 남은 한계는 추가 기록을 기준으로 확인합니다.

## 구현 범위

주 사용 흐름은 **네이버 플러스 스토어 상품 상세 페이지 → SafePick 확장 → 내용 확인 및 분석 동의 → 상품 분석 결과의 구매 전 체크리스트**입니다. 기존 링크 입력·설명 붙여넣기·이미지 상품 정보 추출도 유지합니다.

| Notion 5주차 항목 | 구현 |
| --- | --- |
| 상세 설명·구성품·배송·반품 조건 자동 추출 | `risk_analysis.conditions`에 상세 설명, 구성품, 옵션, 배송, 반품·교환, 보증·AS 원문 반환 |
| 모델·구성품 불일치, 누락, 모호한 표현 탐지 | AI 후보 분류와 서버 원문·유형별 검증, 수집 자료의 정보 부족은 별도 항목 |
| 과도한 할인·구매 압박 표현 체크리스트 | 할인·최저가 주장과 구매 압박 항목, 실제 근거와 확인 방법 제공 |
| 근거 문장과 확인 방법 UI | 확인 항목 카드, 원문 인용, 조건 펼치기, 판매 페이지 링크, 직접 확인 완료 체크 |
| 다양한 상품 유형의 오탐 테스트 | 단위/API 테스트, PC·모바일 UI, 실제 모델 평가 6개 사례 |

## 판단 및 근거 처리

- AI는 기존 모델 설정을 사용하여 엄격한 JSON Schema로 조건 인용·후보 신호를 반환합니다. 호환 엔드포인트도 Structured Outputs를 지원해야 합니다.
- 서버가 공백 정규화 후 실제 설명에 인용이 포함되는지 검사합니다. 표시하는 조건 텍스트도 검증한 원문으로만 구성합니다.
- 메뉴명이나 ‘반품/교환안내’라는 제목만으로 구체적 조건을 확인했다고 처리하지 않습니다. 로그인 뒤 정보·상세 페이지 참조 안내는 구체적 조건을 추측하지 않습니다.
- 모델 불일치는 서로 다른 모델 코드와 원문 두 개, 구성품 불일치는 포함/제외 안내와 원문 두 개를 요구합니다. 호환 기종 나열과 ‘미포함·별도 구매’처럼 일관된 제외 안내는 불일치로 취급하지 않습니다.
- ‘오늘 배송’, 정상적인 배송 마감, 10% 쿠폰, 명확한 배송·반품 조건, 네이버 공통 신고 안내의 오탐을 검증합니다.
- 할인 확인 기준은 무조건 최저가/최저가 보장 같은 주장 또는 70% 이상 할인 표현입니다. 사기 확률이나 통계적으로 검증된 위험 임계값이 아니라 가격·조건을 추가 확인할 표현 기준입니다.
- 정보 부족은 `needs_check`, 원문이 있는 표현/불일치는 `attention`으로 구분합니다. 배송·반품은 기본 확인 대상이며 세트/번들/구성품 안내가 있는 자료만 구성품 누락을 추가 확인합니다.
- AI/응답 오류는 `unavailable`, 설명 부족은 `insufficient`로 표시합니다. 분석 실패를 안전 또는 신호 없음으로 바꾸지 않습니다.
- 상품 정보 수정 즉시 이전 체크리스트를 숨기고, `/comparisons`에 원래 수집한 `sale_text`를 함께 보내 다시 분석합니다. 확인 완료 체크는 새로운 분석에서 초기화합니다.

실제 네이버 사례는 [앞서 실제 수집한 자료](validation/2026-10-28/naver-window-product/README.md)를 재사용했습니다. 이번 평가에서 네이버 페이지를 새로 수집한 것은 아닙니다. 기존 상품 정보 추출부터 새 위험 신호 분석까지 실제 API 함수와 모델을 호출했습니다. 반품 안내의 원문에 있는 신선/냉장/냉동 식품 등의 적용 대상도 원문 그대로 표시하며 모든 상품에 같은 조건을 적용한다고 해석하지 않습니다.

최종 결과: [실제 모델 평가 JSON](validation/2026-10-28/week5/live-evaluation.json). 작은 사례 집합의 기능 검증이며 모든 상품에 대한 정확도나 오탐률을 입증하지 않습니다.

## 실행 및 한계

```cmd
cd apps\api
python -m unittest discover -s tests -v
python tests/live_risk_evaluation.py
```

두 번째 명령은 기존 OpenAI 비용이 발생합니다. UI 테스트는 모바일 폴더에서 `node tests/risk-ui.cjs`, `node tests/week4-ui.cjs`, `node tests/material-ui.cjs`로 실행하며 Playwright와 실행 중인 로컬 웹(8081)이 필요합니다. 별도 설치 경로는 `PLAYWRIGHT_MODULE`로 지정합니다. 확장 테스트는 격리 프로필의 Edge를 사용하며 사용자의 원래 프로필에는 설치하지 않습니다.

- 운영 API는 새로운 키/수집 API 없이 설명 분석용 OpenAI 호출 1회를 추가합니다. 공식 비교 미지원 브랜드도 체크리스트는 제공합니다.
- 이미지의 상품 정보 추출은 유지하지만 위험 신호 원문 검증은 텍스트 설명만 사용합니다. 이미지만 있으면 설명 부족으로 안내합니다.
- 접힌 안내·이미지 설명·수집 글자 수 제한 때문에 누락된 내용은 추측하지 않습니다. 확장에서 안내를 펼치고 다시 수집하거나 텍스트를 추가해야 합니다.
- 근거 인용 검증이 의미 해석의 완전한 정확성을 보장하지는 않습니다. 사용자 확인이 필요한 판단 보조 결과이며 사기/가품/안전성 인증이나 확률 점수가 아닙니다.
- 확인 완료 체크의 영구 저장은 구현하지 않았으며 분석 결과 저장은 6주차 범위입니다. iOS·Android 실기기는 별도 검증이 필요합니다.
