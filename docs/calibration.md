# 라벨 사례로 주의 수준·신뢰 점수 보정하기

SafePick의 주의 수준과 신뢰 점수는 아직 **임시 규칙**입니다. 가중치(공식 25 · 설명 20 · 배송·반품 15 · 판매자 25 · 시세 15), 시세 기준(중앙값의 50% · 70%), 미확인 기준의 반영 비율(0.5)은 실제 사례로 확인하지 않은 값입니다. 이 문서는 실제 판매 페이지에 정답(라벨)을 붙여 모으고, 그 사례로 규칙이 얼마나 맞는지 재고, 더 나은 설정을 찾는 방법을 설명합니다.

## 라벨

| 라벨 | 뜻 | 근거로 인정하는 예 |
| --- | --- | --- |
| `trusted` | 정상 판매로 볼 근거가 있음 | 공식 브랜드 스토어, 대형 유통사 공식 입점 스토어, 직접 구매해 정상 수령한 판매처 |
| `risky` | 사기·가품·미배송 등 피해 근거가 있음 | 경찰청·서울시 전자상거래센터 등 공공기관 사기 사이트 공지, 피해 신고 여러 건, 가품 판정, 직접 겪은 피해 |
| `unlabeled` | 아직 판단할 근거가 없음 | 근거를 찾기 전의 사례. 평가 지표에는 들어가지 않습니다 |

라벨에는 반드시 근거(`--source`)를 적습니다. SafePick의 분석 결과를 보고 라벨을 정하면 규칙이 자기 자신을 맞추는 셈이 되므로, **분석과 무관한 외부 근거**로만 정합니다.

## 사례 모으기

1. 판매 페이지에서 SafePick 확장 프로그램의 `현재 페이지 가져오기`를 누르고, 미리보기 텍스트를 전부 복사해 파일(예: `page.txt`)로 저장합니다. 판매자 정보와 반품 안내를 펼친 뒤 가져와야 합니다.
2. 사례를 추가합니다.

```powershell
cd apps/api
python calibration.py add --label risky --source "서울시 전자상거래센터 사기 사이트 공지 2026-10" --url "https://..." --text-file page.txt
```

3. 분석 결과를 저장합니다. 사례마다 OpenAI·Serper·국세청 API를 한 번씩 호출하며, 이미 저장된 사례는 건너뜁니다.

```powershell
python calibration.py snapshot
```

위험 사이트로 의심되는 페이지는 확장 수집용으로만 열고, 로그인·결제·파일 내려받기를 하지 마세요.

## 평가와 보정

```powershell
python calibration.py report   # 현재 설정의 성적. data/calibration/report.json에 사례별 결과 저장
python calibration.py tune     # 가중치·시세 기준 후보 50개를 비교해 상위 5개 출력
```

`report`와 `tune`은 저장한 스냅샷만 다시 계산하므로 외부 호출이 없습니다. 지표는 다음과 같습니다.

| 지표 | 뜻 | 목표 |
| --- | --- | --- |
| 위험 사례를 '낮음'으로 놓침 | 위험 사례가 `낮음`으로 나온 수 | 항상 0 |
| 위험 사례 탐지율 | 위험 사례 중 `높음`·`보통`의 비율 | 높을수록 좋음 |
| 정상 사례 오경보율 | 정상 사례 중 `높음`·`보통`의 비율 | 낮을수록 좋음 |
| 정상 사례 '낮음' 비율 | 정상 사례를 실제로 안심시킨 비율 | 높을수록 좋음 |
| 점수 분리도 | 정상 사례의 점수가 위험 사례보다 높을 확률 (0.5는 구분 못 함) | 1에 가까울수록 좋음 |

`tune`은 위험 사례를 놓치지 않는 설정을 먼저, 그다음 탐지율에서 오경보율을 뺀 값이 큰 설정을, 마지막으로 점수 분리도가 높은 설정을 위에 올립니다. 결과를 자동으로 적용하지 않습니다. 후보가 낫다면 `risk_assessment.py`의 `WEIGHTS`·`CREDIT`과 `market_price.py`의 `FAR_BELOW_PERCENT`·`BELOW_PERCENT`를 직접 바꾸고 테스트를 고칩니다.

**실제 라벨 사례가 종류별 10개보다 적으면** `tune` 결과는 참고용입니다. 적은 사례에 맞춘 설정은 새 사례에서 틀리기 쉬우므로, 사례가 30~50개 이상 쌓인 뒤 설정을 바꾸는 것을 권합니다.

## 지금 들어 있는 사례

- 실제 판매 페이지 10개: 2026-10-28에 확장으로 수집한 자료입니다. 컬리N마트(7개)와 소니코리아 공식 스토어(1개)는 공식 입점·브랜드 스토어라는 근거로 `trusted`, 일반 스마트스토어 2개는 `unlabeled`입니다. 판매 가격은 수집 당시 값이고, 시세는 스냅샷을 만든 날의 검색 결과입니다.
- 가상 사례 6개(`syn-` 접두사): 미등록 사업자번호, 시세의 1/4 가격, 구성품 모순, 모호한 반품 등 규칙이 동작하는지 보기 위한 예시입니다. `tune`에서 기본으로 제외되며 보정 근거로 쓰지 않습니다.

**실제 `risky` 사례는 아직 없습니다.** 위험 사례를 모으는 것이 이 단계에서 가장 중요한 일입니다.

## 파일

- `data/calibration/cases.jsonl`: 사례 목록 (id, url, title, label, label_source, synthetic, captured_at, note)
- `data/calibration/texts/<id>.txt`: 수집한 페이지 텍스트
- `data/calibration/snapshots/<id>.json`: 분석 결과 전체
- `data/calibration/report.json`: 마지막 `report` 결과
