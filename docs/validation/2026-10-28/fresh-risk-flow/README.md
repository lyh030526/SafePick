## 발견한 오탐과 수정 후 확인 범위

메모리카드에서 AI가 `지금 결제 시 모레도착`과 `멤버십 시작하고`를 구매 압박 근거로 내보냈고, 기존 서버 검사도 이를 허용하여 보통으로 분류했습니다. 인용문 자체는 원문에 있었지만 배송 안내를 구매 압박으로 해석한 것이 잘못됐습니다.

- 배송·출고·도착을 안내하는 조건부 ‘지금 결제 시/하면’ 문구는 명시적인 별도 긴급 구매 표현이 없으면 구매 압박에서 제외했습니다.
- 주의 항목의 각 인용문을 개별 확인하여, 배송이나 멤버십 안내가 구매 압박 근거에 섞여 표시되지 않도록 했습니다. ‘오늘만·한정 수량·지금 구매하세요’ 같은 실제 구매 압박은 유지합니다.
- 전체 백엔드 테스트 **69개 통과**: 실제 배송 문구와 배송/구매 압박/무관한 문구가 섞인 사례를 추가했습니다.
- 수정 후 같은 판매 페이지를 새로 열었지만 네이버가 **HTTP 429**로 제한했습니다. 이 접근 제한 화면에서 수집을 멈췄으며, 프록시·다른 프로필·로그인 등으로 우회하거나 재요청을 반복하지 않았습니다.
- 그 후 **이번 최초 실행에서 정상 수집했던 메모리카드 원문**을 실제 웹/API/모델로 재분석하여 주의 표현이 제외되고 판단 보류로 표시되는지 별도로 검증했습니다. 이 단계는 새 페이지 수집이 아닙니다. 따라서 ‘수정 후 같은 페이지를 새로 수집해 전체 과정을 다시 통과했다’고 주장하지 않습니다.

판단 보류는 안전/위험 판정이 아니라 현재 규칙의 낮음 조건을 충족할 만큼 확인하지 못했다는 뜻입니다. 이번 실제 상품 집합에는 사기/악성 판매 페이지의 정답 라벨이 없으므로 높음·보통·낮음 분류의 실측 정확도나 위험 신호 재현율을 입증하지 않습니다.

## 실제 앱 전달 및 화면 확인

8081은 기존 다른 서버가 사용 중이고 SafePick 웹은 8082에서 실행 중이었습니다. 앱 주소를 중간에 바꾸는 테스트를 피하기 위해 확장 **0.2.1**에 실행 중인 로컬 앱 주소(8081/8082) 선택을 추가했습니다. 새 권한이나 외부 주소 전송, 설정 저장은 추가하지 않았습니다. 이번에는 팝업에서 8082를 선택한 뒤 확장이 실제로 8082 앱 탭을 여는 것을 확인했습니다.

최초 5개 모두 다음을 검사했습니다.

- 네이버 실제 HTTP 200 상품 페이지에서 새로 읽은 텍스트/제목/원래 상품 URL을 전달.
- 확장 동의 전 전송 불가, 앱 분석 동의 전 API 요청 없음, 동의 후 실제 API 요청 1회.
- 제출 자료와 수집 자료의 일치, 확장의 수집 시각이 해당 테스트 시작 이후인지 확인.
- API HTTP 200, 설명 분석 completed, 원래 URL과 browser_extension 출처 유지.
- 모든 조건/체크리스트 인용의 원문 존재 확인. 별도로 수행한 의미 검토에서 배송 안내 오탐 1개 발견.
- 응답의 주의 수준과 앱 표시의 일치, 모바일 390px 가로 넘침/앱 JavaScript 오류 없음.

확장 주소 선택 후 기존 수집·동의·전달·이미지·모바일 390px/PC 1440px 회귀 테스트도 통과했습니다. 이 회귀 테스트는 가상 페이지/API 응답을 사용하며 위의 실제 사이트 검증과 구분합니다. TypeScript·ESLint도 통과했습니다.

- [이번 수집 원문의 수정 후 실제 API/UI 재분석](captured-memory-reanalysis/live-ui-api.json), [재분석 화면](captured-memory-reanalysis/live-memory-card-390.png): 새 네이버 수집은 아닙니다.

실행 명령은 모바일 폴더에서 `node tests/live-fresh-risk-flow.cjs`입니다. Playwright 설치 경로는 `PLAYWRIGHT_MODULE`, 앱 주소는 `UI_APP_ORIGIN`으로 지정하며 현재 기본 검증 앱은 8082입니다. `LIVE_FLOW_CASES=memory-card` 등으로 일부 사례만 선택할 수 있고 `LIVE_FLOW_OUTPUT`으로 결과 폴더를 지정합니다. 실제 사이트/모델 요청이 발생하므로 접근 제한이 발생하면 반복 실행하지 않고 기록을 확인합니다.
