# 구매 전 주의 수준

2026-10-28에 기존 원문 근거·체크리스트에 주의 수준 표시를 추가했습니다. API `risk_analysis.assessment`와 결과 화면의 ‘구매 전 주의 수준’ 카드에서 같은 서버 판정을 사용합니다. 사기 확률이나 검증된 판매자 신뢰도 모델이 아닌 **초기 규칙 기반 분류**이며 실제 악성 판매 페이지의 라벨 데이터로 보정한 결과는 아닙니다.

추가 검증: [실제 페이지 새 수집부터 등급 화면까지](validation/2026-10-28/fresh-risk-flow/README.md). 판매 중인 5개와 중지 화면 2개를 새로 확인했습니다. 배송 안내 오탐을 수정했고 전체 백엔드 테스트는 69개입니다. 수정 후 해당 페이지 재접근은 429로 제한되어, 이번에 정상 수집한 자료의 실제 API/UI 재분석과 구분해 기록했습니다.

## 분류 규칙 v1

아래 순서로 적용합니다. 추가 LLM 호출 없이 기존 분석에서 원문 검증을 통과한 근거를 사용합니다.

| 수준 | 적용 기준 | 예시 |
| --- | --- | --- |
| 판단 보류 | AI 분석 실패/자료 부족 | 이미지뿐인 자료, AI 서비스 오류 |
| 높음 | 모델명 또는 구성품 모순 항목에 서로 다른 근거 인용 2개 이상 | 동일 옵션 케이블 포함 ↔ 미포함 |
| 보통 | 모호한 조건·강한 할인 주장·구매 압박 등 근거가 있는 주의 항목 | 오늘만 90% 할인, 지금 구매 |
| 낮음 | 주의 항목이 없고 공식 동일 상품 근거·상세 설명·배송·반품 원문이 확인되며 필수 확인 항목이 남지 않음 | 세 축의 근거를 확인했고 추가 신호 없음 |
| 판단 보류 | 주의 항목은 없지만 위의 낮음 조건을 충족하지 못함 | 공식 비교 미지원 브랜드, 검색 실패, 반품 안내 미수집 |

확인된 주의 신호가 있으면 공식 검색 실패/조건 누락과 함께 `높음` 또는 `보통`으로 표시합니다. 정보 부족 자체를 위험 신호로 올리지 않고, 반대로 신호가 없다는 이유로 부족한 자료를 `낮음`으로 내리지 않습니다. 공식 비교의 `similar`, `not_found`, `unknown`은 명백한 사기나 모델 모순의 증거로 사용하지 않습니다. ‘미지원 브랜드’에는 낮음 판정을 유보하는 보수적인 초기 기준을 사용합니다.

동일 상품 확인은 `comparison.status=exact`뿐 아니라 선택한 공식 페이지의 동일 상품 결과와 원문 근거가 존재해야 인정합니다. 가격 차이나 판매자의 이름은 등급의 단독 근거로 삼지 않습니다. `found`는 관련 원문이 일부 있다는 뜻이며 반품 기한·비용·예외를 빠짐없이 확인했다는 뜻은 아닙니다. 원문 검증도 의미 분류의 정확성을 보장하지 않으므로 아래 체크리스트와 실제 선택 옵션을 함께 확인해야 합니다.

## API와 화면

`assessment`는 `level`, `label`, `summary`, `reasons`, `missing_checks`, `criteria`, `rule_version`을 반환합니다. `criteria`에는 공식 정보 비교·판매 설명·배송/반품 확인 상태가 들어갑니다. 0~100점이나 확률은 반환하지 않습니다.

- `POST /analyses`와 보정용 `POST /comparisons`에서 비교 결과와 설명 분석을 모아 매번 새로 계산합니다.
- 페이지 수집 실패/이미지뿐인 입력/AI 오류의 기본 응답도 판단 보류입니다.
- 화면에 수준, 판정 이유, 세 축의 확인 상태, 아직 확인할 정보를 표시하고 상세 원문 체크리스트를 이어서 제공합니다.
- 체크리스트 확인 완료 체크는 사용자 메모입니다. 체크했다고 위험 근거가 사라지거나 등급이 내려가지 않습니다.
- 상품 정보를 수정하면 기존 등급과 체크리스트를 숨기고 재분석 결과를 표시합니다.
- 과거 API처럼 `assessment`가 없는 응답은 판단 보류로 표시하고 재분석을 안내합니다.

예를 들어 ‘오늘만 90% 할인! 지금 구매’는 보통, 같은 상품의 서로 다른 모델 코드가 확인되면 높음입니다. 안내가 부족한 정상 판매 페이지는 판단 보류가 될 수 있으며 위험하다는 뜻이 아닙니다. 낮음도 정품·배송 이행·판매자 안전을 보증하지 않습니다.

## 검증

- 전체 Python 단위/API 테스트 **67개 통과**. 새 정책의 8개 테스트는 낮음의 근거 요건, 검색 실패/미지원/유사 상품, 배송·반품 부족, 구매 압박/할인, 두 종류 모순, 반박된 후보, 서비스 오류, API 및 보정 재계산을 검증합니다.
- TypeScript·ESLint 통과. 390px/1440px에서 높음·보통·낮음·판단 보류, 정보 부족, 체크해도 등급 유지, 보정 후 이전 결과 숨김, 오류/설명 부족, 가로 넘침을 검증합니다. 이 화면 회귀는 fixture API 응답을 사용합니다.
- [기존 실제 상품 10개 및 합성 모델 결과 5개의 정책 재평가](validation/2026-10-28/risk-levels/replayed-evidence.json). **새 네이버 수집이나 새 모델 추출이 아닌 저장된 근거 재평가**입니다. 실제 10개는 공식 상품 동일 여부 등을 확정하지 못해 모두 판단 보류입니다. 판매 페이지가 위험하다는 의미가 아닙니다. 합성 모델 모순·구성품 모순은 높음, 과도한 할인/압박/모호한 반품 사례는 보통으로 구분합니다.
- [실제 웹/API/모델 연결 결과](validation/2026-10-28/risk-levels/live-ui-api.json): 이전 실제 블루베리 수집 자료로 새 분석을 실행합니다. 공식 비교 미지원이므로 판단 보류이며 원래 상품/자료가 유지되는지 확인합니다. 새 판매 페이지 수집은 아닙니다. 웹 8082에서 API 8000으로 실제 요청하며 API 모킹을 사용하지 않습니다.

```powershell
cd apps/api
python -m unittest discover -s tests -v
python tests/evaluate_risk_levels.py

cd ../mobile
$env:PLAYWRIGHT_MODULE = '<Playwright 모듈의 절대 경로>'
$env:UI_APP_ORIGIN = 'http://localhost:8082'
node tests/risk-ui.cjs
node tests/live-risk-level.cjs
```

마지막 명령은 실행 중인 웹/API와 기존 OpenAI 설정을 사용합니다. 기존 8081 포트의 다른 프로세스는 종료하지 않았습니다. 검증 웹은 8082이며 개발 CORS는 localhost 8081/8082를 허용합니다. 확장의 기본 앱 주소는 8081이고, 확장 0.2.1부터 팝업에서 8082를 직접 선택할 수 있습니다.
