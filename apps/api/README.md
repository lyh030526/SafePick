# SafePick API

## 실행

```powershell
python -m pip install -r requirements.txt
py -m uvicorn main:app --reload --port 8000
```

## 환경 변수

`.env.example`을 `.env`로 복사한 뒤 `OPENAI_API_KEY`를 설정하면 자동 추출을 사용합니다. 기본 OpenAI 주소가 아닌 엔드포인트를 사용할 경우 `OPENAI_BASE_URL`에 해당 주소를 설정하고, 그 엔드포인트에서 지원하는 모델을 `OPENAI_MODEL`에 입력합니다. 키가 없으면 모든 추출 항목은 `확인 불가`로 반환되어 앱에서 직접 보정할 수 있습니다.

공식 사이트 검색은 [Serper](https://serper.dev/)의 Google Search API를 사용합니다. `SERPER_API_KEY`를 설정하면 지원 브랜드의 공식 도메인으로만 결과를 검색합니다. 키가 없거나 검색 요청이 실패한 경우에도 분석은 완료되고, 검색을 사용할 수 없다는 안내를 반환합니다.

판매자 사업자 확인은 판매 자료의 '판매자 정보'에서 사업자등록번호를 찾아 검증 숫자를 확인한 뒤, 공공데이터포털의 [국세청 사업자등록 상태조회 API](https://www.data.go.kr/data/15081808/openapi.do)로 계속·휴업·폐업·미등록 상태를 조회합니다. 포털에서 활용신청 후 받은 인증키를 `DATA_GO_KR_SERVICE_KEY`에 넣습니다(Encoding·Decoding 키 모두 가능). 네이버·쿠팡·11번가·G마켓 등 오픈마켓 운영사와 '통신판매중개자' 안내 바로 뒤의 사업자 정보는 판매자로 보지 않습니다. 11번가처럼 판매자 번호를 보안 문자 뒤에 숨기는 곳은 판매자를 확인할 수 없습니다. 폐업·미등록이면 주의 수준이 `높음`, 휴업·번호 형식 오류면 `보통`이 되고, 공식 상품 일치가 없을 때는 정상 사업자로 확인돼야 `낮음`이 될 수 있습니다. 키가 없거나 조회에 실패하면 `조회 불가`로 표시하고 판단을 보류합니다. 등록 상태는 판매자의 신뢰도를 보증하지 않습니다. 같은 키로 공정거래위원회 [통신판매사업자 등록상세 API](https://www.data.go.kr/data/15126315/openapi.do)도 조회합니다(포털에서 이 API를 별도로 활용신청해야 합니다). 번호로 신고된 정상영업 기록의 상호·통신판매업 신고번호가 페이지와 다르면 다른 업체의 번호를 적어 둔 것일 수 있어 `보통`, 신고가 모두 폐업·취소면 `보통`이 됩니다. 자체 쇼핑몰이 신고된 쇼핑몰 주소와 다른 도메인에 있거나 신고 기록이 없으면 추가 확인 항목이 되어 `낮음`이 나오지 않습니다. 네이버·쿠팡 같은 오픈마켓 판매자는 도메인을 비교하지 않습니다. 페이지에 '상호' 항목이 없으면 신고된 상호가 페이지 어딘가(푸터 등)에 나오는지 확인하고, 없으면 추가 확인 항목이 됩니다.

네이버·11번가처럼 사업자등록번호를 인증 뒤에만 보여 주는 오픈마켓에서 상호와 대표자가 보이면 `오픈마켓 표시 판매자`로 판매자 기준에 일부 점수(0.75)를 줍니다. 마켓의 입점 심사를 거쳤다는 뜻일 뿐이므로 국세청 확인을 대신하지 않고 `낮음`도 열지 않습니다. 공정위 통신판매사업자 파일([data.go.kr 15083251](https://www.data.go.kr/data/15083251/fileData.do), 지역별 CSV, 매주 갱신)을 공정위 홈페이지(정보공개 → 사업자정보공개 → 통신판매사업자 → 지역별 자료 다운로드)에서 받아 `data/mail_order/`에 넣고, 저장소 루트에서 `python apps/api/mail_order_index.py build "data/mail_order/*.csv"`로 색인(`data/mail_order/index.sqlite`, git 제외)을 만들면, 정상영업 중인 같은 상호·대표자가 정확히 한 곳일 때 그 사업자번호로 국세청·공정위 조회까지 합니다. 열이 밀린 줄(값 안의 쉼표, 약 4%)은 잘못된 번호와 이어질 수 있어 색인에서 뺍니다. 색인이 없으면 이 단계는 건너뜁니다.

가격 시세 비교는 같은 `SERPER_API_KEY`로 Google 쇼핑(한국) 결과를 검색합니다. 상품명에 같은 모델명이 들어간 새 상품 판매처만 남기고(중고·리퍼·렌탈·액세서리·묶음 상품과 중고 거래 플랫폼, 원화가 아닌 가격 제외). 판매 상품 자체가 이어패드·케이스처럼 호환·교체용 부속품이면 같은 부속품 단어가 들어간 판매처만 비교합니다, 중앙값에서 크게 벗어난 가격을 뺀 뒤 3곳 이상 남으면 판매가를 시세 중앙값과 비교합니다. 중앙값의 50% 미만이면 `시세보다 지나치게 저렴`으로 주의 수준이 최소 `보통`, 70% 미만이면 `시세보다 저렴`으로 추가 확인 항목이 되어 `낮음`이 나오지 않습니다. 모델명이 없거나 비교할 판매처가 부족하면 판단을 보류하며, 이것만으로 위험하다고 보지 않습니다. 분석 1회마다 Serper 검색이 한 번 더 발생합니다. 기준값은 임시이며 실제 사례로 보정할 예정입니다.

도메인 확인은 사용자가 입력한 주소의 도메인 등록 정보를 각 등록기관의 공개 RDAP(IANA 목록, `.kr`은 KISA)로 조회합니다. 등록되지 않았거나 만료·삭제 대기인 도메인은 페이지를 읽지 못해도 `높음`, 등록 180일 미만에 1년만 등록한 도메인은 `보통`, 등록 1년 미만이면 추가 확인 항목입니다. 2026년 서울시전자상거래센터가 공표한 사기 쇼핑몰은 모두 이런 신규·단기 도메인이었습니다. 오래된 도메인은 점수에 더하지 않습니다(오픈마켓 판매자는 모두 마켓 도메인을 쓰고, 오래된 도메인을 사거나 정상 사이트가 해킹되는 경우가 있습니다). 오픈마켓 주소는 확인하지 않고, 조회 실패는 위험으로 보지 않습니다.

쿠팡처럼 일반 판매자가 올린 오픈마켓 상품에는 다음 규칙이 더해집니다. 쿠팡은 판매자의 상호·대표자·사업자번호·통신판매업 신고번호를 인증 없이 보여 주므로(`상호/대표자` 한 칸에 두 값) 국세청·공정위 확인이 그대로 적용됩니다.

- 오픈마켓 상세 설명은 대부분 이미지라서, 구성품을 글에서 찾지 못해도 확인 항목으로만 보여 주고 `낮음`을 막지 않습니다. 반품 안내의 "구성품 누락 시 반품 불가" 같은 문장만으로는 구성품 확인을 요구하지 않습니다.
- 통신판매업 신고번호의 연도(`2026-용인처인-01238`)가 올해이면 운영 이력이 없는 신규 판매자로 보고 `판매자 운영 기간`을 추가 확인 항목으로 둡니다(자체몰의 신규 도메인과 같은 역할).
- 리뷰에 챗봇의 맺음말("다음 제품 리뷰 작성을 도와드릴까요?")이 남아 있거나, 25자 이상의 같은 문장이 세 번 이상 반복되면 `리뷰 패턴` 주의 항목(`category=review_pattern`)이 되어 최소 `보통`입니다. 모델 호출 없이 페이지 글자에서 찾습니다.
- 공식 비교를 지원하지 않는 브랜드는 `공식 정보 비교`를, 같은 모델의 판매처가 부족하거나 모델명이 없으면 `가격 시세`를 점수 기준에서 뺍니다. 확인할 수 없는 기준에 절반 점수를 주는 대신, 판매자와 판매 설명·구매 조건이 점수를 정합니다.

쿠팡이 직접 파는 로켓배송 상품(판매자 표 없이 "판매자: 쿠팡(주)")은 `쿠팡 직접 판매`(`platform_direct`)로 판매자 기준을 충족합니다. 사업자번호 칸에 일본 등록번호(`T`+13자리)나 "해당사항 없음"이 있거나 주소가 해외인 판매자는 `해외 판매자`(`overseas`)로, 국내 기록으로 확인할 수 없다는 점과 해외 배송의 반품·관부가세를 안내하고 `낮음`이 나오지 않습니다. 쿠팡의 `판매자 평가`(예: 93% (70))를 함께 읽으며, 10명 이상이 평가했는데 80% 미만이면 최소 `보통`입니다.

### 같은 상품 판매 페이지 비교

`POST /group-analyses`는 같은 상품을 파는 판매 페이지 2~10곳(`listings`, 각 항목은 확장 프로그램이 읽은 `provided_text`가 있는 `/analyses` 요청)을 받아 각각 분석한 뒤 비교합니다. 공식 비교나 웹 시세를 찾지 못한 페이지는 **다른 판매 페이지들의 가격 중앙값**을 시세로 써서 같은 기준(50% 미만 `보통`, 70% 미만 추가 확인)을 적용합니다. 해외 구매대행의 높은 가격이 중앙값을 끌어올리므로, 마켓이 직접 파는 가격은 지나치게 싸다고 보지 않고, 그 가격의 90% 이상인 페이지도 마찬가지입니다. 다른 페이지 대부분과 모델 코드가 다르면 같은 상품·옵션인지 확인하라고 알립니다(띄어 쓴 상품명은 비교하지 않음). 결과는 주의 수준 → 점수 → 가격 순으로 순위를 매기고, '낮음' 중 가장 싼 곳을 요약에 알려 줍니다. 페이지마다 전체 분석을 하므로 10곳이면 AI·검색 호출이 10배이고 몇 분 걸립니다.

확장 프로그램(0.6.0)에서 판매 페이지를 가져온 뒤 `같은 상품 비교 목록에 추가`를 페이지마다 누르고(목록은 이 브라우저의 확장 저장소에 비우기 전까지 남음), `비교하기`를 누르면 SafePick 앱이 새 탭(`#safepick-group`)으로 열리고 목록은 그 탭의 세션 저장소로 전달됩니다(URL에 담기에는 커서). 이를 위해 확장 프로그램에 `localhost:8081/8082` 접근 권한이 추가되었습니다.

확장 프로그램은 다른 상품 카드가 4개 이상 반복되는 추천 목록("이런 상품은 어때요?")을 읽지 않아, 다른 상품의 가격과 설명이 이 상품의 것으로 섞이지 않습니다. 쿠팡 서버는 주소만으로 페이지를 가져오는 요청을 막으므로(403) 쿠팡 상품은 확장 프로그램으로 읽어야 합니다.

신뢰 점수(0~100)는 판단 기준 5개(공식 정보 25, 판매 설명 20, 배송·반품 15, 판매자 사업자 25, 가격 시세 15)의 가중치로 계산합니다. 적용할 수 없는 기준(미지원 브랜드의 공식 정보, 비교 판매처가 없는 시세)은 빼고 남은 기준의 가중치로 나눕니다. 정상 사업자의 통신판매업 신고 연도를 알면 `판매자 운영 기간`(25)을 더합니다: 5년 이상 `확인됨`, 2~4년 `일부 확인`, 1년 이하 `추가 확인`. 공식 상품 일치나 시세 범위 확인이 없으면 상품 자체를 비교하지 않은 것이므로 `낮음`의 점수 상한은 95입니다. 그래서 쿠팡의 이름 없는 브랜드 상품은 오래 영업한 판매자 95, 2~4년 93, 1년 92처럼 판매자 이력에 따라 갈립니다. `확인됨`은 가중치 전부, `주의 항목 있음`은 0, 확인하지 못한 기준은 절반을 받습니다. 이 비율을 주의 수준의 점수 구간(높음 0~29, 보통 30~59, 판단 보류 30~79, 낮음 80~100) 안에 비례해 놓습니다. 그래서 점수가 주의 수준과 어긋나지 않으면서 같은 수준 안에서도 확인된 근거가 많을수록 높아지며, 점수 구간 이름은 `구매 보류 권장`, `주의 필요`, `대체로 양호`, `근거 양호`입니다. `coverage_percent`는 근거가 확인된 기준의 가중치 비중이며, 40% 미만이면 점수를 매기지 않습니다(`점수 보류`). 다만 높음·보통처럼 결정적인 근거가 있으면 점수를 냅니다. 사기 확률이 아니라 확인한 근거의 요약이며, 가중치는 실제 사례로 보정할 예정입니다.

라벨을 붙인 실제 판매 페이지로 주의 수준과 신뢰 점수가 얼마나 맞는지 재고 설정을 비교하려면 `python calibration.py`를 사용합니다. 사례 추가, 분석 저장, 평가(`report`), 후보 비교(`tune`) 방법은 [라벨 사례로 보정하기](../../docs/calibration.md)에 있습니다.

`POST /analyses`와 `POST /comparisons`는 AI·검색 비용이 드는 요청이므로 클라이언트 IP당 분당 `SAFEPICK_RATE_LIMIT_PER_MINUTE`회(기본 30, `0`이면 해제)로 제한하며, 초과하면 429를 반환합니다. 제한 기록은 프로세스 메모리에만 있어 서버를 재시작하면 초기화됩니다. 본문 크기는 `/analyses` 12MB, `/comparisons` 256KB로 제한합니다.

## 현재 API

- `GET /health`: 서버 상태를 확인합니다.
- `GET /brands`: 초기 지원 브랜드와 공식 도메인 목록을 반환합니다.
- `POST /analyses`: 공개 상품 페이지 또는 사용자가 제공한 텍스트·이미지에서 상품 정보를 구조화합니다.
- `POST /comparisons`: 사용자가 보정한 상품 정보로 공식 검색과 비교를 다시 수행합니다.

`POST /analyses`는 추출된 브랜드가 지원 대상인지 확인하고, LLM이 만든 브랜드·모델 기반 검색어로 공식 도메인만 검색합니다. 검색 결과는 `official_lookup`에 담깁니다. 직접 수집 시 내부망·로컬 주소와 HTML이 아닌 응답은 차단합니다. 수집한 공개 텍스트 또는 사용자가 제공한 텍스트·이미지를 OpenAI에 전달하며, 결과가 없는 필드는 `확인 불가`로 처리합니다.

## 사용자 제공 텍스트·상품 이미지 분석

판매 페이지 접근이 제한되면 앱에서 상품 설명을 붙여넣거나 JPG·PNG·WebP 이미지를 첨부할 수 있습니다. [브라우저 확장 프로그램](../extension/README.md)도 같은 분석 API를 사용합니다. 추가 수집 API는 연결하지 않습니다.

`POST /analyses`의 선택 필드:

```json
{
  "product_url": "https://smartstore.naver.com/demo/products/12345?option=blue",
  "provided_text": "브랜드·모델·가격·판매자 등 확인할 상품 설명",
  "page_title": "상품 제목",
  "input_source": "browser_extension",
  "captured_at": "2026-10-28T03:00:00Z",
  "images": [{"mime_type": "image/png", "base64_data": "이미지의 base64 문자열"}]
}
```

- `provided_text` 또는 `images`가 있으면 판매 페이지를 다시 요청하지 않고 해당 자료만 추출에 사용합니다. 공식 사이트 검색과 비교는 기존대로 진행합니다. 링크는 분석 대상의 출처를 표시하기 위해 필요합니다.
- 설명은 최대 12,000자입니다. 이미지는 최대 3장, 한 장 4MB·총 8MB이며 실제 파일 형식·디코딩·해상도를 검증합니다. 분석 요청 전체는 실제 수신 바이트 기준 12MB까지 받습니다.
- 이미지는 기존 OpenAI Chat Completions의 `image_url` content part로 전달합니다. 기본 `gpt-5.4-mini`는 이미지 입력을 지원하며, 커스텀 엔드포인트/모델도 이미지 입력을 지원해야 합니다. 지원하지 않거나 호출에 실패하면 직접 보정하도록 안내합니다.
- 흐리거나 없는 글자, 외형으로만 유추한 모델/브랜드, 충돌하는 정보는 `확인 불가`로 처리하도록 요청합니다. 추출 결과는 사용자가 확인·수정해야 하며 외형만으로 정품/판매자 신뢰도를 판정하지 않습니다.
- `source.kind`는 `server_page`, `user_text`, `browser_extension`, `user_images`, `mixed`를 구분합니다. `image_count`와 사용자가 제공한 `captured_at`도 반환합니다. 제공 자료와 URL의 일치나 수집 시각을 인증하지 않습니다.
- 운영 API는 이미지/설명 원본을 디스크나 DB에 저장하지 않습니다. 검증 오류 응답에도 원본 base64와 설명을 포함하지 않습니다. 첨부 화면에서 AI 전송을 안내하며, 기존 OpenAI 이용료는 발생할 수 있습니다.

실제 이미지 입력 확인: `python tests/live_material.py`. **가상 상품 캡처와 빈 이미지 두 장을 실제 OpenAI에 전송**하므로 API 비용이 발생합니다. 성공 결과는 `docs/validation/2026-10-28/material-input/`에 기록합니다.

참고: [OpenAI 이미지 입력](https://developers.openai.com/api/docs/guides/images-vision?api-mode=chat), [Expo SDK 57 ImagePicker](https://docs.expo.dev/versions/v57.0.0/sdk/imagepicker/).

## 공식 정보 비교 (4주차)

`POST /analyses`의 `comparison` 필드는 공식 페이지를 직접 읽어 비교한 결과입니다. 페이지를 수집하지 못해 보정 입력으로 전환된 경우에는 `null`이며, 보정 후 `/comparisons`로 비교할 수 있습니다.

| status | 화면 표시 | 의미 |
| --- | --- | --- |
| `exact` | 동일 상품 확인 | 상품명 또는 모델명과 공식 원문 근거가 확인됨 |
| `similar` | 유사 상품 확인 | 관련 상품이나 모델·세대·옵션의 차이 또는 불확실성이 있음 |
| `not_found` | 확인되지 않음 | 이번 검색·확인한 페이지에서 동일 상품을 찾지 못함 |
| `unknown` | 확인 불가 | 미지원 브랜드, 접근 차단, 추출 실패 또는 근거 부족 |

- 공식 페이지는 최대 3개를 읽고, 이동하는 모든 URL에 공식 도메인 제한과 공개 주소 검사를 적용합니다.
- 국내 공식 사이트를 우선 검색하고, 입력 링크가 공식 도메인이면 그 페이지도 비교 근거 후보에 우선 포함합니다.
- `pages[].facts`에 공식 상품명·모델명·가격·통화·구매처 안내가 포함됩니다. `evidence`는 공식 페이지에 실제 존재하는 원문이며 필드와 연결해 검증합니다.
- `price.difference`는 판매가에서 공식 가격을 뺀 값입니다. `difference_percent`는 공식 가격 대비 차이(%)입니다. 동일 상품·단일 가격·같은 통화가 확인된 경우에만 Decimal로 계산하며, 유사 상품·할부·범위·쿠폰 조건·누락 정보는 계산하지 않습니다.
- 공식 도메인 판매 링크는 별도로 표시하고, 판매자명이나 안내 문구만으로 외부 판매자를 공식 판매처로 인증하지 않습니다.

보정 비교 요청 예시:

```json
{
  "product_url": "https://shop.example.com/product",
  "product": {
    "brand_name": "Apple",
    "product_name": "AirPods Pro 3",
    "model_number": "확인 불가",
    "price": "299000",
    "currency": "KRW",
    "seller_name": "확인 불가",
    "components": ["확인 불가"]
  }
}
```

## AI 상품 설명 위험 신호 분석 (5주차)

`POST /analyses`는 `risk_analysis`와 `sale_text`를 추가로 반환합니다. 네이버 플러스 스토어 확장에서 전달한 상품 설명도 같은 경로로 분석합니다. 공식 비교 미지원 브랜드도 판매 설명 체크리스트는 사용할 수 있습니다.

- `risk_analysis.status`: `completed`(수집 범위 분석 완료), `insufficient`(설명 부족), `unavailable`(AI 설정/호출/응답 오류).
- `conditions`: 상세 설명(`description`), 구성품(`components`), 옵션(`options`), 배송(`shipping`), 반품·교환(`returns`), 보증·AS(`warranty`). 각 값은 `status`, `text`, `quotes`를 가지며, 표시하는 `text`도 검증한 원문에서만 구성합니다.
- `checklist`: 모델 표기 불일치, 구성품 불일치, 모호한 조건, 할인·최저가 주장, 구매 압박, 수집 자료에서 확인하지 못한 정보. 각 항목에는 `kind`, `title`, `explanation`, `quotes`, `how_to_check`가 있습니다.
- `kind=attention`은 실제 인용이 있는 표현/불일치 확인 항목이고, `needs_check`는 수집 범위에서 조건을 확인하지 못한 항목입니다. 후자는 실제 페이지에 안내가 없다는 뜻이 아닙니다.
- 누락 확인은 배송·반품을 기본으로 하고, 세트/번들/구성품 안내가 있는 자료만 구성품 누락을 추가 확인합니다. 식품처럼 모델명이 없는 상품을 일괄 위험으로 표시하지 않습니다.
- AI는 엄격한 JSON Schema로 조건 인용과 신호 후보를 반환합니다. 설정한 모델/엔드포인트는 Structured Outputs를 지원해야 합니다. 기본 모델은 기존 `gpt-5.4-mini` 설정을 유지합니다.
- 서버가 공백을 정규화한 인용문과 원문을 대조하고, 메뉴명·안전거래 신고 안내·단순 배송 마감·명시된 호환 기종 등을 걸러냅니다. 할인 확인 기준은 무조건 최저가/최저가 보장 같은 주장 또는 70% 이상 할인 표현이며, 사기 가능성의 통계적 기준이 아닙니다.
- 모델 불일치는 서로 다른 코드가 있는 두 인용을, 구성품 불일치는 포함과 제외 안내가 있는 두 인용을 요구합니다. 공식 검색 실패나 미지원 브랜드 자체를 위험으로 취급하지 않습니다.
- 근거 없는 0~100점 사기 확률/안전 등급은 생성하지 않습니다. 분석 실패 시에도 안전하다고 표시하지 않습니다.

이미지는 기존 상품 정보 추출에 사용합니다. 위험 신호의 **원문 문장 검증은 텍스트 설명만** 대상으로 하며 이미지뿐이면 `insufficient`입니다. 필요한 상세 설명이나 배송·반품 안내를 펼쳐 확장으로 다시 가져오거나 텍스트로 추가하세요.

사용자 보정 후 재분석하려면 `/comparisons`에 기존 `product_url`, `product`와 함께 원래 자료인 `sale_text`, `page_title`을 전달합니다. 앱은 수정 즉시 이전 체크리스트를 숨기고 새 비교/분석 결과를 표시합니다. `sale_text`는 클라이언트에서 재분석을 위해 보유하는 자료이며 운영 API가 DB/디스크에 저장하지 않습니다.

이 단계는 기존 OpenAI에 설명 분석 호출 1회를 추가합니다. 별도의 수집 API나 키는 필요하지 않습니다. 확인 완료 체크는 현재 화면에서만 유지되며 영구 저장은 6주차 범위입니다.

검증: [5주차 구현 및 테스트 기록](../../docs/week5-verification.md). 실제 모델 평가는 `python tests/live_risk_evaluation.py`로 실행하고 AI 비용이 발생합니다. [OpenAI Structured Outputs 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs).

실제 네이버 상품 추가 검증과 남은 제한은 [실제 상품 12개 검증 기록](../../docs/validation/2026-10-28/week5-real-products/README.md)에 정리했습니다. 인용문을 이중 인코딩한 응답과 DOM 공백 차이를 처리한 뒤 실제 원문 구간을 반환하며, 메뉴 제목만으로 조건을 확인했다고 처리하지 않습니다. `무료교환반품`에 직접 붙은 괄호 제한도 함께 보존합니다.

## 테스트

구매 전 주의 수준은 `risk_analysis.assessment`에서 높음·보통·낮음·판단 보류로 반환합니다. 원문 검증된 모델/구성품 모순은 높음, 그 외 확인할 표현은 보통, 상세 설명·배송/반품 확인과 신호 없음에 더해 공식 상품 일치 또는 국세청 정상 사업자 확인이 있고, 시세보다 싸지 않을 때만 낮음입니다. 공식 상품 일치 없이 낮음이 되면 요약에 공식 상품과의 동일 여부와 페이지에 적힌 사업자번호의 실제 판매자 여부는 확인하지 않았다고 표시합니다. 미지원 브랜드/검색 실패/정보 부족/분석 오류는 낮음의 근거가 아니며 판단 보류로 남깁니다. 추가 모델 호출이나 확률 점수 없이 계산합니다. 판매 설명 검토는 같은 자료를 3번 분석해 2번 이상 나온 조건·주의 항목만 남기고, 같은 자료를 다시 분석하면 저장해 둔 결과를 돌려줘 분석할 때마다 수준이 바뀌지 않게 합니다(검토 비용은 3배). 상품명을 되풀이하거나 '브랜드 소니'처럼 짧은 항목·값 쌍은 상세 설명으로 세지 않습니다. [분류 규칙과 검증](../../docs/risk-levels.md).

```cmd
python -m unittest discover -s tests -v
```

서버와 키를 설정한 뒤 실제 Apple 공식 사이트 연동을 점검하려면 `python tests/live_comparison.py`를 실행합니다. 이 명령은 실제 검색 API와 AI를 호출합니다.

지원 브랜드별 실제 검증 기록과 403 등 남은 제한은 [4주차 검증 결과](../../docs/week4-verification.md)에 정리되어 있습니다.
